01 · teaching python to decide

From straight-line code to branching code

Every program so far has run top to bottom, one line after another. Real programs need to branch: if the user is 18 or older, let them in — otherwise, don't. That's conditional logic, and it starts with the fact that comparisons give us Booleans.

🔮 Based on last class's comparison operators, what does this print? 
age = 20
print(age >= 18)

True

💬 A condition is just a question whose answer is True or False. Python uses that answer to decide what happens next.

02 · if & indentation

The simplest decision

age = 20

if age >= 18:
    print("You are an adult.")

You are an adult.

if starts a decision, age >= 18 is the condition, : marks the start of the block, and the indented line runs only when the condition is True.

age >= 18 ?
True
print()
False
skip
🔮 Same words, only the indentation removed — run fine, run differently, or fail? 
age = 20

if age >= 18:
print("You are an adult.")

IndentationError: expected an indented block after 'if' statement on line 3

💬 Indentation isn't cosmetic — it's part of Python's syntax. Python uses it to know which lines belong to the if. Four spaces is the normal convention.

🔮 What prints if age = 15, with no else yet? 
age = 15

if age >= 18:
    print("You are an adult.")

(nothing is printed)

💬 15 >= 18 is False, so Python just skips the indented line — there's no output at all, and that's expected, not a bug.

✅ Takeaway Code belonging to an if must be indented — this is Python enforcing structure, the same way it enforced syntax back in Class 1.
03 · else

Handling the false case

🔮 What prints now, with age = 15 and an else added? 
age = 15

if age >= 18:
    print("You are an adult.")
else:
    print("You are not an adult.")

You are not an adult.

if handles the condition being true; else handles everything else.

A first useful program — try predicting the output for a score of 75, then for 32, before reading on:

score = int(input("Enter your score: "))

if score >= 40:
    print("You passed!")
else:
    print("You failed.")
04 · elif & order

More than two possibilities

score = int(input("Enter your score: "))

if score >= 90:
    print("Grade A")
elif score >= 80:
    print("Grade B")
elif score >= 70:
    print("Grade C")
elif score >= 60:
    print("Grade D")
else:
    print("Grade F")

Python checks conditions top to bottom and stops at the first one that's True — it never looks at the rest.

🔮 With score = 85, which grade prints — and which lines does Python never even look at? 
85 >= 90 → False
85 >= 80 → True

Grade B

💬 Once score >= 80 is True, Python prints Grade B and skips every remaining elif/else — it doesn't keep checking just to be thorough.

Now the big one. score = 95 — what prints?

if score >= 60:
    print("Grade D")
elif score >= 90:
    print("Grade A")

💬 The output is Grade D. 95 is obviously greater than 90 — but Python checks score >= 60 first, and that's already True, so it stops right there and never reaches the elif. The order of your conditions matters.

if score >= 90:
    print("Grade A")
elif score >= 60:
    print("Grade D")

Put the more specific, higher-priority condition first.

🤖 AI moment If you guessed Grade A, paste this into an AI assistant: "I expected score = 95 to print Grade A here, but it printed Grade D. Walk me through why, without just telling me to reorder the conditions." Then reorder the conditions yourself and re-run with score = 95 to prove it now prints Grade A.
✅ Takeaway elif chains stop at the first True condition — put more specific, higher-priority conditions before broader ones.
05 · boolean conditions

Conditions built from and / or / not

🔮 Work out age >= 18 and has_id step by step before revealing 
age = 20
has_id = True

if age >= 18 and has_id:
    print("Entry allowed.")
else:
    print("Entry denied.")

Entry allowed.

💬 age >= 18 → True, has_id → True, True and True → True — so the if block runs.

🔮 has_ticket = False, is_guest = True, joined with or — what prints? 
if has_ticket or is_guest:
    print("You may enter.")
else:
    print("You cannot enter.")

You may enter.

💬 or only needs one condition to be true.

🔮 is_raining = False — does if not is_raining: print its message? 
if not is_raining:
    print("Let's go outside.")

Let's go outside.

💬 not False becomes True, so the message displays.

06 · nested conditions

A decision inside a decision

Sometimes one decision only makes sense after another. First check age, then — only if that passes — check for an ID.

age = 20
has_id = True

if age >= 18:
    if has_id:
        print("Entry allowed.")
    else:
        print("You need an ID.")
else:
    print("You are too young.")
age >= 18 ?
has_id ?

True → "Entry allowed."
False → "You need an ID."

Outside both boxes → "You are too young." (only reached when the outer check is False)

The inner if is only ever checked when the outer one is true — that's what "nested" means. Compare it to the logical-operator version:

if age >= 18 and has_id:
    print("Entry allowed.")

When conditions are simple and independent, and is often shorter and easier to read. Nesting earns its keep when the second decision genuinely depends on the first, or each level needs a different action — like distinguishing "too young" from "has no ID" above, which the and version can't do in one line.

🤖 AI moment (optional stretch) With both versions working, ask an AI assistant: "Here are two ways I wrote the same entry check — one nested, one using and. When would each be the better choice?" Then try adding a distinct "too young" vs "no ID" message to the and version yourself and see whether it can express it as cleanly as the nested version does.

A second example — predict what happens for a wrong username, and separately for a right username with a wrong password, before reading on:

username = input("Enter username: ")
password = input("Enter password: ")

if username == "admin":
    if password == "python123":
        print("Login successful.")
    else:
        print("Incorrect password.")
else:
    print("Unknown username.")

Wrong username → the password check is never reached. Right username, wrong password → the inner else runs. That's the whole point of nesting: the second check only exists inside the first check's true path.

✅ Takeaway Both patterns are correct. Reach for and when conditions are independent; nest when a decision only makes sense after an earlier one, or each branch needs its own action.
07 · ternary operator

Compressing a simple if-else

This five-line block sets one variable:

age = 20

if age >= 18:
    status = "Adult"
else:
    status = "Minor"
🔮 Guess how Python might compress this to a single line, then reveal 
age = 20
status = "Adult" if age >= 18 else "Minor"
print(status)

Adult

💬 This is called a conditional expression, usually just called the ternary operator.

The pattern reads like a sentence:

value_if_true if condition else value_if_false

message = "Pass" if score >= 40 else "Fail" reads as: "Set message to Pass if the score is at least 40, otherwise set it to Fail."

When not to use it Don't chain ternaries to save lines — "A" if score>=90 else "B" if score>=80 else "C" if score>=70 else "F" is technically valid but much harder to read than a normal if/elif/else. Save the ternary for genuinely simple two-way choices.
✅ Takeaway The ternary operator isn't new logic — it's just a compact way of writing a simple if-else.

Mini project: eligibility checker

Ask for age and registration status; the user is eligible only if they're at least 18 and registered.

age = int(input("Enter your age: "))
registered = input("Are you registered? ")

if age >= 18 and registered == "yes":
    print("You are eligible.")
else:
    print("You are not eligible.")
🔮 Predict the output for three cases, then reveal — and think about why we use and, not or

age=20, registered="yes" → eligible
age=20, registered="no" → not eligible
age=16, registered="yes" → not eligible

💬 or would let an unregistered adult in, or a registered minor in — either alone would satisfy an or. The rule needs both conditions, which is exactly what and enforces.

Mini challenge: discount calculator

₹5,000+ → 20% discount. ₹2,000+ → 10% discount. Otherwise → no discount.

amount = float(input("Enter purchase amount: "))

if __________:
    discount = 20
elif __________:
    discount = 10
else:
    discount = 0

print("Discount:", discount, "%")
🔮 Which condition has to come first — the 5,000 check or the 2,000 check, and why? 
amount = float(input("Enter purchase amount: "))

if amount >= 5000:
    discount = 20
elif amount >= 2000:
    discount = 10
else:
    discount = 0

print("Discount:", discount, "%")

💬 The 5,000 check has to come first — this is the same order-of-conditions rule from earlier in this card. If the 2,000 check came first, an amount of 6,000 would match it and stop there, before ever reaching the correct 20% tier.
